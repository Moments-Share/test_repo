# Business Validation Studio — デプロイ手順（Vercel）

このフォルダは、**固定URLを先方に渡す → こちらが更新 → 先方は開くだけで最新版＆AIが動く** を実現するための一式です。
APIキーはサーバー側（Vercelの環境変数）にだけ置くので、**ブラウザ（＝先方）にキーは一切出ません**。

---

## 仕組み（なぜAIが動くのか）

- 画面（React）は、AIを呼ぶとき `https://api.anthropic.com` を直接叩かず、**自分のサーバー `/api/claude` に投げます**。
- `/api/claude`（`api/claude.js`）が、環境変数のAPIキーを付けて Anthropic API に中継します。
- だから、先方はURLを開くだけでAI（採点・壁打ち・売上予測）が動き、キーは漏れません。

---

## 機能

| 画面 | できること |
|---|---|
| 新しいアイデアを検証 | お題 → AIが3案 → 市場・顧客競合・収益構造・売上予測 → 事業計画シミュレーター → 3分ピッチ＋その場決裁 |
| 進行中の事業を検証 | 並走事業を一括採点（A〜Eランク）→ 1億円到達可能性100点（20項目）→ AI壁打ちで不足証拠を埋める |
| **撤退ライン・成功確率** | 成功確率（%）と根拠 → 確率を上げる打ち手（チェックすると確率に加算）→ 3〜4個のステージゲート（指標・継続ライン・撤退ライン）＋投資/期間/工数の上限 → 実績を入れると「継続／ピボット／撤退」を機械判定 → プレモーテム → 判断者と合意日を記録。ブラウザに自動保存、テキスト/Excelで書き出し、ピッチ資料にも反映 |

1億円到達可能性スコア（進行中の事業の詳細評価）：6大項目×26小項目を各0〜5で採点し、大項目の配点で重み付けして100点に換算します。未検証の項目は0点にせず、評価カバレッジとして別に表示します。

| 大項目（配点） | 小項目 | 対応する専門家の基準 |
|---|---|---|
| 顧客課題・需要（20） | 課題の強さ／顧客検証／支払意思／実績・継続性／**なぜ今か** | Desirability・Traction・Timing |
| 市場・顧客母数（15） | 1億への市場余力／顧客像／顧客アクセス | Market |
| 1億円売上モデル（20） | 数学的成立性／獲得現実性／単価妥当性／成長再現性 | Viability |
| 収益性（15） | 粗利構造／獲得後利益／投資回収性 | Viability |
| 勝てる理由（15） | 顧客価値の差／自社優位性／模倣困難性／**自社資産の活用**／**競合・代替への備え** | Moat・Strategic fit・Adaptability |
| 実行・推進体制（15） | 販売体制／生産・提供能力／3年以内の実現性／**推進オーナー（熱量×権限）**／**投入工数の確保**／**巻き込み力** | Feasibility・Team |

配点は `src/App.jsx` の `SCORE_MODEL` の `max` で変えられます（先方とすり合わせて確定する前提）。推進体制の3項目が弱いか未検証の場合は、詳細評価の画面に「人がボトルネック」と表示されます。

撤退ラインの判定ルール（アプリ側で計算。AIの気分では変わらない）：

1. 累計投資・期間・投入工数のどれかが上限に達したら **撤退**（期間は最終ゲート通過済みなら除く）
2. それ以外は、実績を入れた最新ゲートで判定：継続ライン以上＝**継続**、撤退ライン以下＝**撤退**、その間＝**ピボット**
3. ピボットは1回まで。2回目のピボット判定は **撤退**

## Vercel で公開する

1. https://vercel.com に GitHub アカウントでログイン
2. 「Add New… → Project」→ このリポジトリ（`validation-studio`）を Import
   - Root Directory はそのまま（リポジトリ直下）。Framework Preset は Vite が自動で選ばれる
   - ※ 1_CoreShift100 内の `apps/validation-studio` から公開する場合だけ、Root Directory をそのフォルダに変更
3. Environment Variables に追加：
   - `ANTHROPIC_API_KEY` = Anthropic の APIキー（https://console.anthropic.com で発行。`sk-ant-...`）
   - `APP_PASSCODE` = 合言葉（任意だが推奨。設定すると、初回に合言葉を入れた人だけがAIを使える）
   - `ANTHROPIC_MODEL` = 使うモデル（任意。未設定なら `claude-sonnet-5-5`）
4. 「Deploy」→ `https://<プロジェクト名>.vercel.app` が発行される

**APIキーは絶対にコードや GitHub に書かない**（Vercel の環境変数にだけ置く）。サンプルデータはすべて架空です。顧客の実データはコミットしないでください。

以後、main に push すると、同じURLのまま自動で最新版になります。

> モデルはサーバー側（`ANTHROPIC_MODEL`）で固定。ブラウザから差し替えはできず、`max_tokens` も上限 8000 に制限しています（URLが広まってもAPI代が暴れないように）。AIの応答待ちに備えて `vercel.json` で関数のタイムアウトを60秒にしています。

## コードを更新したいとき

- `src/App.jsx` を編集 → GitHubにpush → Vercelが自動で再デプロイ → 同じURLが最新に。
- 注意：Claude とのやり取りで更新した `business-forge.jsx` を `src/App.jsx` に**丸ごと上書きすると、撤退ライン機能と合言葉対応が消えます**。上書きではなく差分を取り込んでください（先頭の `callClaude` はこのデプロイ用）。

## モデルについて

- 既定は `claude-sonnet-5-5`。もし `model not found` 等のエラーが出たら、**自分のAPIアカウントで使えるモデルID**に `ANTHROPIC_MODEL` を変えてください。
- 速度・コスト重視なら Haiku 系、品質重視なら Sonnet / Opus 系。

## セキュリティ・運用メモ

- キーはサーバー環境変数のみ。`.env` はGitに上げない（`.gitignore`済み）。
- 社外にURLを渡すときは `APP_PASSCODE` を設定してください。合言葉は各ブラウザに保存され、2回目以降は聞かれません。
- コスト目安：1事業の詳細評価＝数回のAI呼び出し。残高を見ながら運用できます。
